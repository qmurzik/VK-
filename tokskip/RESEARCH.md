# Этап 0 — исследование TikTok

## Что удалось и что нет

**APK TikTok к задаче приложен не был** (в репозитории только проект VK Enhancer), а скачать его
из сборочного окружения не получилось: зеркала APK отдают 403 / Cloudflare-челлендж. Поэтому
**ни один класс ниже не проверен декомпиляцией конкретной версии**. Раздел «Ожидаемые точки входа»
основан на открытых данных о внутреннем устройстве TikTok (публичные исследования, исходники модов
и SDK ByteDance) и отмечен как гипотеза.

Чтобы это не было слабым местом, исследование встроено в сам продукт:

| Инструмент | Что делает |
|---|---|
| `tools/research.sh TikTok.apk` | Без jadx ищет в dex-файлах якоря, на которые опираются хуки (имена классов, строки `WEBVTT`, `aweme_id`, методы плеера), и оценивает степень обфускации. Если `jadx` установлен — декомпилирует и перечисляет классы, где встречается каждый якорь. |
| Экран «Дамп UI» в приложении | Через службу доступности сохраняет дерево узлов текущего экрана TikTok в файл (`Android/data/com.qmurzik.tokskip/files/dumps/`). Видны id описания, субтитров, полосы прогресса, их `rangeInfo` и поддержка `ACTION_SET_PROGRESS`. |
| Подробный лог LSPosed-модуля | При первом ролике пишет в «Логи» список геттеров модели ролика и модели видео; пишет, какой класс плеера и какие методы найдены, сколько хуков поставлено. Результаты DexKit кэшируются в `cache/tokskip_dexkit.properties` внутри данных TikTok. |

Порядок работы с конкретной версией: `tools/research.sh` → установить APK TokSkip → включить
«Подробный лог» → открыть пару роликов → прочитать «Логи» и сделать «Дамп UI». Найденные id
вписываются в «Настройки → элементы экрана» без пересборки.

## Ожидаемые точки входа (гипотеза, по открытым данным)

### Пакеты
- `com.zhiliaoapp.musically` — глобальный TikTok.
- `com.ss.android.ugc.trill` — региональная сборка (Азия).

### Модель ролика и лента
- Модель: `com.ss.android.ugc.aweme.feed.model.Aweme`. Класс — Gson-бин, поэтому исторически
  **не переименовывается** (keep-правила), как и его геттеры:
  - `getAid(): String` — id ролика (`aweme_id`);
  - `getDesc(): String` — описание;
  - `getAuthor(): User` → `getUniqueId()` (@ник), `getNickname()`;
  - `getVideo(): Video` → `getDuration()` (мс), `getPlayAddr(): UrlModel` → `getUri()` / `getUrlKey()`
    (по ним плеер получает источник);
  - субтитры: в `Video` — список caption-info (`cla_info` / `caption_infos`) с языком и **URL
    файла WebVTT**. Текст субтитров в ответе ленты не лежит — его отдельно скачивает и парсит сам TikTok.
- Ответ ленты: `/aweme/v1/feed/`, `/aweme/v2/feed/` → `FeedItemList.getItems(): List<Aweme>`.
  Транспорт — TTNet (Cronet) и всё чаще protobuf, а не JSON, и парсер обфусцирован. Поэтому
  **хук ставится не на парсер, а на `Aweme.getAid()`**: фид-код вызывает его для каждого элемента
  сразу после разбора (дедупликация, предзагрузка), то есть до показа ролика. Объект ролика
  обрабатывается один раз (WeakHashMap).

### Плеер
- SDK ByteDance `com.ss.ttvideoengine.TTVideoEngine` — публичный API SDK, имена сохраняются
  (вызываются из обёрток и через JNI):
  - `getCurrentPlaybackTime(): int` (мс), `getDuration(): int` (мс);
  - `seekTo(int, SeekCompletionListener)`;
  - `setVideoID(String)`, `setDirectURL(String)`, `setDirectUrlUseDataLoader(String, String)` — источник;
  - `play()`, `pause()`.
- Сверху — обёртки TikTok (`playerkit`, `simplemediaplayer`), сильно обфусцированные. Модуль их
  не трогает.
- Связь «плеер ↔ ролик»: источник, переданный в `setVideoID`/`setDirectURL`, сопоставляется
  с `playAddr.uri`/`urlKey` ролика из ленты.

### Субтитры
- Авто-субтитры — WebVTT. Парсер ищется DexKit как методы, использующие строку `"WEBVTT"`;
  любой строковый аргумент или результат, похожий на субтитры, разбирается `CaptionParser` и
  прикрепляется к ролику, который сейчас играет.

### UI (служба доступности)
- Id ресурсов TikTok ужаты ресурсным шринкером и меняются между версиями (исторически встречались
  `desc`, `title`, но полагаться на них нельзя). Поэтому `ScreenReader` использует:
  1. id из настроек (взятые из «Дампа UI»);
  2. исторические id как подсказку;
  3. эвристики: автор — подпись «@ник», описание — самый длинный текст в нижней половине экрана,
     полоса прогресса — узел с `rangeInfo`/классом `SeekBar` шире трети экрана;
  4. только узлы `isVisibleToUser` — пейджер держит соседние ролики в дереве.
- Полоса прогресса у TikTok появляется не у всех роликов (у длинных). Если её нет, позиция
  оценивается по времени с появления ролика, а вместо перемотки выполняется резервное действие.

## Насколько всё обфусцировано (ожидание)

| Слой | Обфускация | Как TokSkip это обходит |
|---|---|---|
| Модели (`Aweme`, `Video`, `User`) | низкая — keep для Gson | имя класса → иначе DexKit «класс с `getAid(): String`»; поля — по геттерам или по `@SerializedName` |
| Сеть / парсер ленты | высокая, protobuf | не хукается; вместо него — геттер id модели |
| Парсер субтитров | высокая | DexKit по строке `"WEBVTT"` |
| TTVideoEngine | низкая — публичный SDK | имя класса → иначе DexKit «класс с `getCurrentPlaybackTime()`» |
| Обёртки плеера / UI-код | высокая | не используются |
| Ресурсы (id view) | ужаты | эвристики + id из «Дампа UI» в настройках |

## Отказоустойчивость

- Каждая функция модуля (лента, субтитры, плеер) ставится независимо внутри `runCatching`; если
  класс или метод не найден — в лог пишется причина, функция отключается, TikTok работает без
  изменений.
- Все хуки — `ExceptionMode.PROTECTIVE`: исключение в коде модуля не уходит в TikTok.
- Результаты DexKit кэшируются по отпечатку APK (размер + время + версия сигнатур) и
  пересчитываются после обновления TikTok.
- Модуль работает только в главном процессе TikTok.
