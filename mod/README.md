# VK Mod — модифицированный клиент ВКонтакте для Android

Патч официального APK: ядро мода (Java, отдельный dex) встраивается в приложение, в smali остаются только
пять тонких хуков. Всё остальное — настройки, темы, фильтры ленты, приватность — живёт в ядре и подчиняется
единому реестру функций.

| | |
|---|---|
| Исходник | `com.vkontakte.android` **8.200**, versionCode **59646**, сборка AppGallery (`_hw`), arm64-v8a + armeabi-v7a, Android 9+ (minSdk 28) |
| SHA-256 исходного APK | `7ea8fab1a56060fdb69183dda26d75d00c6dccaef8f83fc2448626d20aefa35d` |
| Подпись исходника | `O=VKontakte`, SHA-256 сертификата `057d974412032066f1b5edb1fdb550f71854189815c806b27c4d486fb4f1ef32` |
| Результат | `vkmod-signed.apk`, подписан **тестовым** ключом (см. «Подпись и push») |

Исходный bundle не потребовался: файл — единый APK, объединять через APKEditor нечего.

> **1.0.1 чинит баг запуска из 1.0.0**: приложение не стартовало (сплэш → чёрный экран → выход на рабочий стол,
> без краша). Причина: перехватчик сети читал тело **любого** ответа `/method/...` как текст, даже без
> `Content-Type` (например бинарные/файловые ответы), и пересобирал его — такой «пустой» путь портил байты.
> Теперь тело трогается только при явном текстовом `Content-Type`. Заодно реклама/трекеры/промо выключены
> **по умолчанию** (раньше были включены сразу): без реального устройства для проверки включать агрессивные
> сетевые правила «из коробки» было поспешно. Включите нужное в «Настройках мода» после первого успешного запуска.

> **Важно: функции проверены без устройства.** В среде сборки нет эмулятора (нет KVM). Каждая точка хука найдена
> и применена скриптом, ссылки хуков на код ядра проверяются при сборке, логика фильтров/правил/MessagePack/тем/медиа
> покрыта JVM-тестами (33 теста), сквозной путь перехватчика проверен на OkHttp-подобной имитации. Работу на
> телефоне подтверждаете вы по [чек-листу](docs/CHECKLIST.md). Таблица [STATUS.md](docs/STATUS.md) честно
> разделяет ✅ / ⚠️ / ❌.

## Что внутри

- **Темы.** Хук на единственный резолвер цветов VK (`DesignContextExt.g(attr, ctx)`): атрибут классифицируется по *имени*
  (`vk_ui_*`, `vk_legacy_*` → слот «акцент», «шапка», «пузыри»…) и цвет подменяется из итоговой палитры
  (пресет → Material You → AMOLED → ваши цвета → прозрачность панелей). 19 готовых тем, редактор с живым
  превью, импорт/экспорт JSON.
- **Сеть.** Один перехватчик OkHttp в конструкторе `OkHttpClient`: вырезает рекламу/рекомендации/репосты/слова из
  ответов (JSON и MessagePack), подменяет «прочитано», «печатает», «в сети» и аналитику ответом `{"response":1}`,
  блокирует трекерные и рекламные хосты, собирает ссылки на медиа в «Журнал медиа».
- **Интерфейс.** Хук на `LayoutInflater` VK обрабатывает каждую новую XML-вёрстку: скрытие элементов по id, шрифт,
  выделение текста, форма аватарок, отключение вибрации и звуков. Нижняя панель настраивается отдельно.
- **Жизненный цикл.** Блокировка PIN/биометрией, масштаб текста и плотность, флаги окна, прокси, иконки.
- **Надёжность.** Каждый хук обёрнут: ошибка → функция отключается (запоминается), запись в лог, приложение
  продолжает работать с оригинальным поведением.

## Настройки мода

Иконка **«VK Mod»** в лаунчере или **долгое нажатие на вкладку профиля** в нижней панели VK. Поиск, категории,
описание под каждой функцией, пометка ⚠ у частично работающих. Раздел сверстан программно и берёт цвета из
активной темы, то есть сам подчиняется движку тем.

> Отступление от задания: раздел **не встроен в стандартный экран настроек VK**, а открывается отдельным
> экраном. Встраивание в экран настроек VK без устройства для отладки слишком хрупко.

## Сборка

Нужно: JDK 17+, Python 3, apktool, Android build-tools 35 (d8, zipalign, apksigner), `android.jar` платформы 35,
JUnit 4.13 и org.json (для тестов).

```bash
mod/build.sh all                       # компиляция ядра, тесты, core.dex
mod/make_apk.sh path/to/vk.apk out.apk # полный конвейер: распаковка → патч → сборка → dex → zipalign → подпись
VKMOD_FAST=1 mod/make_apk.sh vk.apk    # только пересобрать ядро и подпись (патчи smali не менялись)
```

Конвейер: `apktool d` → `build.sh` (тесты + `core.dex`) → `patcher/patch.py` → `patcher/verify_refs.py`
(падает, если smali ссылается на метод, которого нет в ядре) → `apktool b` → `patcher/assemble.py` → `zipalign` → `apksigner`.

**Ресурсы не пересобираются.** apktool/aapt2 не сохраняет числовые ID у ~1400 drawable с именем на `$`, а smali
ссылается на ресурсы числами, поэтому результат `apktool b` для ресурсов не используется. `assemble.py` берёт
оригинальный APK целиком (`resources.arsc`, `res/`, `assets/`, `lib/`) и заменяет только `classes*.dex` (из apktool,
плюс ядро мода последним), `AndroidManifest.xml` (после проверки, что все ресурсы, на которые он ссылается, имеют те же ID
и имена, что в оригинале) и подписи.

## Обновление под новую версию VK

```bash
mod/make_apk.sh new-vk.apk
```

`patch.py` ищет каждую точку по **сигнатуре**, а не по имени обфусцированного класса:

| Патч | Признак поиска |
|---|---|
| `app_attach` | класс из `<application android:name>`, метод `attachBaseContext(Context)` |
| `color_resolver` | static `(ILandroid/content/Context;)I`: `getTheme()` → `resolveAttribute(…)` → `TypedValue.data`, без других вызовов |
| `okhttp` | класс в `okhttp3/` со строкой `"Null interceptor: "`, конструктор `(Builder)`, первое поле `List` |
| `inflater` | подкласс `android.view.LayoutInflater` с `inflate(int, ViewGroup, boolean)` |
| `exact_date` | static `(ILandroid/content/res/Resources;Z)Ljava/lang/String;`, использующий строку `vk_date_ago_now` |
| `split_dex` | первичный dex VK у предела 64K методов — `androidx` и `com/google` переносятся в новый dex |

Скрипт печатает `[ OK ]` / `[MISS]` по каждой точке и пишет `patch_report.json`. Если точка не найдена, зависящие
от неё функции помечаются ❌ (`build.sh status`) и не работают, остальное продолжает работать.

## Подпись и push

APK переподписан. Это значит:

1. **Поверх оригинала не ставится.** Сначала удалите официальный VK (данные приложения удалятся; вход по номеру
   и коду возможен снова).
2. **Push-уведомления могут не работать.** FCM/HMS/RuStore Push привязывают токен к отпечатку подписи
   приложения. Сборка AppGallery (`_hw`) рассчитана на HMS, на устройствах без Huawei-сервисов push в оригинале тоже
   работает иначе. Проверьте на своём телефоне: если push не приходят — это ограничение переподписи.
   Обходные пути: microG с подменой подписи (ваш выбор и риск), либо использовать фоновую синхронизацию.
3. **Вход и сообщения** по описанию не зависят от подписи: VK использует собственную авторизацию. В коде найдена
   проверка хеша подписи (`xsna.uon`) — вероятно, статистика. Это нужно подтвердить на устройстве.
4. Подпись **тестовая**; ключ создаётся скриптом при первой сборке (`vkmod-test.jks`, пароль `vkmodtest`) и в
   репозиторий не входит. Для обновлений «поверх» подписывайте всегда одним и тем же ключом.

## Ограничения и честные замечания

- Не реализовано сознательно: сохранение удалённых и история правок **чужих** сообщений, анонимный просмотр
  историй (затрагивают других людей без их ведома), обход проверок подписи и защит VK.
- Не реализовано технически: автовоспроизведение видео, качество медиа по умолчанию, подтверждение перед отправкой
  голосовых/стикеров, ID в профиле, копирование ссылок, действие двойного тапа, радиус скруглений. Для них нет
  надёжной точки без отладки на устройстве; вместо них добавлены дополнительные фильтры ленты и сервисные функции.
- Темы: резолвер VK покрывает цвета, которые приложение берёт через свой помощник; атрибуты, которые Android
  разрешает сам внутри XML, остаются прежними. Фактический охват узнаете на устройстве.
- Размытие панелей недоступно (только прозрачность). Фон чата — только цвет.
- Журнал медиа: ссылки берутся из ответов сервера; это не кнопки внутри просмотрщика VK.

## Отказ от ответственности

Проект для персональной кастомизации официального клиента на собственном устройстве. Не аффилирован с
ВКонтакте. Распространяйте только скрипты и ядро, а не готовый APK.
